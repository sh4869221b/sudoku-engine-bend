# Bend 2.0.40 compatibility review

Reviewed the [official source comparison](https://github.com/bendlang/bend/compare/v2.0.37...v2.0.40), with the target fixed at `624dd9f4607cd29b0871a9b96d413bfb11e92f52`.
The release API reports stable, non-draft v2.0.40, published 2026-11-06 02:06:29 UTC. The web search's cached v2.0.39 listing was stale; the explicit API and downloaded asset identify 2.0.40.

- `bend2/comp.ts` changes the native runtime command line: only options inside `+RTS` / `-RTS` are consumed, while `--` is now an application argument. QA commands and CLI guidance must migrate. Old/new comparison tools use `qa/runtime_args.py`; `BEND_LEGACY_BINARY` selects only the exact legacy baseline path without a probing process during measurement. `BENDRTS` is cleared in the comparison entrypoint.
- `bend2/main.ts` retains Linux CPU flags `-std=c11 -O3 -lpthread -lm` and runs Clang after forcing GC while retaining the compiler process. The sequential adapter remains relevant. No GPU code is used by this project.
- `bend2/safe.ts` still honors explicit `BENDTT` before checking the auto-build's Lean 4.34.0. Rebuild this release's unmodified `bendtt.lean` using the preserved pinned Lean 4.34.1. The kernel/exporter have substantial changes; previous proof results cannot substitute for new verification.
- Valid check-only output remains exactly `ALL PROOFS CHECK` followed by `Use --verdict for mathematical validity.` Kernel success remains exactly `ALL PROOFS CHECK`. Failed verdicts now include more detailed diagnostics. The adapter continues refusing unsafe/foreign prechecks, export diagnostics and nonexact kernel success.
- Upstream changes include native allocation/sharing, fork scheduling, JS constructor names/tags, Node File effects, and integer intrinsics. Keep Sudoku algorithms, search order, fuel and seeds unchanged and run the existing correctness, proof, lane and differential checks. The active Node lane now also attempts batch/bench file IO, removing the obsolete Bun-only skip because this release supplies Node fs implementations. New `U32.popcount`, `U32.ctz`, and unsafe array access are intentionally outside this compiler migration.
- The ordinary/sequential smoke and JS host harnesses derive from the committed 2.0.37 harnesses. Original attributed fixtures and Apache license are reused from that directory, preserving historical evidence. Real results must be read from this upgrade's evidence, not inferred from source review.

Real smoke tests also identified two intentional diagnostic changes. Unsafe dependencies are now grouped as `defs that depend on @unsafe: D, use, Zero, P`, and rejected JS Nat inputs now say `expected a Nat host number: an integer from 0 to 2^53`. The new harness requires these exact semantics: all four distinct unsafe dependency names, rejection exit 1, and exact host rejection for all six invalid values. Initial failed harness reports are retained; acceptance was updated to match the reviewed upstream formats without changing accepted/rejected values.

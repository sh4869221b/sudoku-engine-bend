## Reproduction

Installed `bend guide` (Bend 2.0.34) and `bend base` signatures take precedence over historical 2.0.x syntax and tooling descriptions. Native compilation used Clang 19.1.7. With those tools installed, set BEND and CC if they are not on PATH. Independent verification is mandatory in `./verify.sh`: provide Lean4.34.0 on PATH for Bend to build its kernel, or set BENDTT to an already-built matching kernel. Then run `./verify.sh`. Build only: `./build.sh`. Runtime: `bin/bend-sudoku --threads 8 solve <puzzle>`. `bend main.bend -- solve <puzzle>` also works. Runtime options precede the `--` separator. `bend main.bend --check-only` replaces historical `--checkup`. Both `bend qa/run.bend` and `bend qa_run.bend` are supported. The modern proof success text is `ALL PROOFS CHECK`, not the historical `All terms check.`

No bundled compiler, generated C/JS, binaries, credentials, or original implementation code are published. Python files are standard-library independent QA and measurements, not engine dependencies. The executable engine, all seven commands, core, generation, rating, batch and benchmark are Bend only. No custom foreign effects or unsafe definitions are used. No CI workflow is configured; the recorded gates were executed locally against final source.

## Exact command contracts and resolved ambiguities

- Inputs are exactly 81 ASCII digits or dots, with `0`/`.` blank. Embedded whitespace is rejected (the strict Scope boundary wins over the older parser task's whitespace-removal wording). Physical file lines accept LF or CRLF; only empty lines and lines beginning `#` are skipped. Files are regular readable files up to 16 MiB; larger files fail with exit 1, never silently process a truncated prefix.
- `solve`: solved81 + exit0; `unsolved` + exit3; invalid input has empty stdout, stderr reason, exit2; fuel has empty stdout/stderr `fuel`, exit4.
- `check`: `valid`, exit0; `invalid length|character|row:i|col:i|box:i`, exit2. Unit indices are zero-based. Initial duplicates are errors before search/rating.
- `count`: `0`, `1`, `2` (two or more) with exit0; fuel has empty stdout/stderr `fuel`, exit4.
- `rate`: normal output is exactly Difficulty / Max technique / Steps / Score, four lines. Completed puzzle is Easy/None/0/0. Empty puzzle is Hard/None/0/0 (RequiresGuess; no existence/uniqueness promise). Contradiction and fuel have no difficulty label or stdout, stderr `contradiction`/`fuel`, exit3/4. Initial invalid input is exit2. Candidate-zero and missing-digit/no-unit-placement contradictions are checked. NS/HS/LC/NP weights are1/2/5/10; score<25 Easy, <60 Medium, elseHard; one actual placement/elimination pattern is one step. No-op patterns are not counted. Tie order is fixed ascending position for NS; row/column/box, unit, digit for HS/LC; unit then member position for NP.
- `generate`: default seed0, count1, clue target32. Seed0 normalizes to2463534242. Subsequent output i uses `(seed+i-1) mod 2^32`. Seed, count, clue values are strict U32, count must be positive, clues0..81. Unknown/missing/repeated options are exit1. Difficulty presets are exactly36/32/28 and are not measured difficulty guarantees.
- Explicit `--clues`, `--difficulty`, and `--minimal` are mutually exclusive, in either argument order. This resolves #8 without pretending an exact clue target and minimality are always jointly possible. `--minimal` ignores the default32 target and processes all removal units. Non-symmetric minimal means every individual retained clue is critical. Symmetric minimal means every retained mirrored pair/central singleton is critical, not ordinary single-clue minimality (#7). Units are shuffled once. A failed removal never needs retry because later clue removal can only add solutions. This one complete sweep therefore establishes the stated minimality; independent QA removes every retained unit again.
- Exact targets never undershoot, including symmetry+80. A reachable target is exact; otherwise the final unique puzzle is printed with exit0 and stderr `TargetUnmet index=<i> seed=<s> target=<requested> reached=<actual>`. Stdout contains only puzzle lines. On fuel, previously completed prefix puzzles remain valid; the failed puzzle and later puzzles are not printed; exit4. The same seed retries deterministically and cannot be assumed to resolve fuel.
- `batch <file> <mode>` uses physical one-based indices, balanced trees with empty right subtrees and four explicit fork-join functions. A tail-recursive scanner handles physical lines and a consuming tree builder avoids repeated take/drop prefix copies. Every non-skipped line produces exactly one result record. Invalid lines skip computation but emit `error:<reason>`. Empty/comment-only, all-invalid, mixed, unsolved and fuel-containing batches all aggregate to exit0 after a successful read. Error/fuel records identify individual failure. Rate error records have `label:- ... status:contradiction|fuel`; normal RequiresGuess is `label:Hard ... status:guess`.
- `bench <file>` solves exactly the actual non-skipped file jobs (no hidden repetition). `bench --generate N` accepts1/10/100/1000/10000, using seeds1..N and36 clues with symmetry/minimal off. File and generate inputs are mutually exclusive. Missing/read failure exit1, empty/invalid file exit2, unsolved/fuel/invalid returned solution exit4. Successful output is `N=... mode=cpu threads=runtime total_ms=... per_ms=...`. Timing excludes generation/read/prevalidation/tree preparation and includes solve plus result validity/clue preservation. `qa/benchmark.py` measures a fixed corpus, warmup then three repetitions at each N and threads1/8/16; it skips10000 only if that thread setting's1000 median exceeds60s.

## Algorithm and proof scope

Array<U32>128 boards and bit1..9 candidate masks are used. Search repeatedly selects the first naked single, otherwise true MRV (lowest position tie), then ascending candidate values. It is sequential bounded DFS. The single global200000 fuel counts each forward node/placement or backtracking transition. Digging gives each uniqueness call20000; rating729 transitions.

**Historical original search implementation, retained for reference below:** Search threads an affine board plus a fixed-capacity affine frame array through the fuel-bounded state machine. Board padding81..107 caches row/column/box occupancy and108 tracks the first empty cell; the public uncached candidate API is unchanged. Every placement (including a forced single) packs its position, old value and remaining candidate mask in a frame; backtracking restores that value before choosing the next alternative. Each cache is rebuilt at search entry and updated on placement/restoration. No board cloning occurs inside search. Generator trial removals use explicit clones to retain the accepted board while running a pure counter. The shuffle is a selection/removal variant of Fisher–Yates; permutations are generated from bounded-index xorshift draws, with the ordinary modulo-reduction bias. Determinism is established for this implementation, not compatibility with an unseen original implementation's seed sequence.


### Current production clarification 2026 10 03

Production `search.run` and `search.run_prepared` dispatch to `adaptivesearch.prepared`. Before activation, row occupancy uses low ten bits and packed empty-column metadata in bits10..18; cache108 tracks the first empty cell. At the first guess, cells are encoded as candidate masks or shifted fixed digits and urgency bits109..111 are maintained. Guess frames carry position, remaining candidates and a guess marker; an encoded board is cloned at each guess and restored before trying another alternative. Forced unwind clears the logical cell. Stale metadata during unwind is not selected from before the next saved guess is restored. Each forward transition or unwind still consumes one actual fuel operation. The earlier no-cloning paragraph describes the retained legacy implementation, not current production.

The unchanged6060-record golden suite consists of3030 actual production terminal/fuel observations and3030 traces through retained legacy `S.selected`/`S.backtrack` transitions. It does not directly prove or exhaustively trace the adaptive snapshot stack. The separate queued-candidate suite runs24000 trace steps, including inactive, backtracking and already-completed states; candidate/urgency/selection checks apply to active forward states. Any additional direct adaptive trace is reported separately with its actual coverage.

The generic batch laws concern the pure `batch_*`/flatten functions. Current ordered streaming IO emits the same output-tree leaves left-to-right, and its actual host IO path is validated by exact CLI/file differentials and source review; no formal host-IO equivalence theorem is claimed.

- `count_many_absorb` proves Many absorbs every one of the four Count constructors.
- `count_add_assoc` proves associativity for all27 triples of the three **decided** counts (Zero/One/Many). The full four-valued table is deliberately runtime-tested for all16 entries. It is not associative: `(One+One)+Fuel=Many`, `One+(One+Fuel)=Fuel`. The source Scope's adjective 'associative' for all four values conflicts with its table; its explicit fuel-free27 proof requirement is followed.
- Four generic structural laws prove each fork-join batch function equals its sequential tree counterpart for every JobTree. They do not prove parser correctness, tree construction or leaf algorithm correctness; input-order/list equivalence is independently runtime-tested for0/1/3/5/100 jobs at1/8/16 threads.
- `mirror_involute_all81` checks every legal cell position by definitional reduction.
- `cell_set_get_boundary_samples` checks actual Array operations at (position,value)=(0,9),(40,1),(80,0),(127,U32_MAX). This is a **finite boundary law**, not arbitrary-array/arbitrary-index/arbitrary-value set/get. Runtime QA covers all128 positions × four values and peer geometry for all81 positions.
- `candidate_mask_empty_cell0` checks the actual candidate API for cell0 on an empty board. This is not a general candidate-soundness theorem. Runtime QA checks bounds on all81 cells in empty and easy boards; independent solution checks cover candidate effects. The original all81 candidate/all128 set-get reduction was narrowed to keep the standard checker usable. The wider cases remain native QA, not stronger formal claims.
- No solver completeness, universal generator validity, uniqueness theorem, or rater soundness proof is claimed. The standard Bend checker and the independent `--verdict` kernel both accept all supplied proofs. On2026-09-30 the official bundled BendTT Lean source was compiled with official Lean4.34.0; the complete `bend PROOF.bend --verdict` run exited0 with `ALL PROOFS CHECK` in12.641s. The earlier timeout was isolated to BendTT export of nested U32 patterns with affine Arrays. Splitting only `search.selected` into Bool helpers resolved it; LAWS.bend and PROOF.bend were preserved byte-for-byte. See lean-verification.json and proof-verdict.log.
